## 1. 事实核查

### 1.1 英语内容 bug（审计中）

已经确认的**结构性事实**（我自己核过）：

- 内容规模：**600 个词条 + 100 句型 + 20 绘本 + 30 拼读关 + 20 听辨对 + 120 关卡**，
  数据文件共约 **355 KB**，全部手写
- 每个词条有 **11 个字段**：`word / ipa / zh / pos / grade / emoji / syll / sent{en,zh} / phonics / tips`
  —— 每个字段都是一处可能出错的地方
- 仓库里**已经有**校验脚本 `tools/en/check_content.py`，我跑了一遍：

  ```
  ✅ 内容校验通过（警告 0 条）
  ```

  **但它查的是「结构」不是「语义」**：词条数、字段是否齐全、id 是否唯一、
  交叉引用是否悬空、音频文件是否存在。

**这就是 bug 藏身的地方** —— 结构全对、内容是错的。例如：

| 类型 | 现有脚本能否发现 |
|---|---|
| 音标标错 | ❌ 查不出（它不知道 cow 该读 /kaʊ/） |
| 中文释义错 / 有歧义 | ❌ 查不出 |
| 例句里根本没包含这个词 | ❌ 查不出 |
| 拼读分组把不符合规则的词放进去 | ❌ 查不出 |
| 答案标错 | ❌ 查不出 |
| 音频引用不存在的文件 | ✅ 能查 |
| id 重复 / 字段缺失 | ✅ 能查 |

> 我抽样核对了 30 条音标，**这批是对的**，说明错误更可能集中在
> 释义、例句、拼读分组、关卡配置上。具体清单等审计结论（第 6 节）。

## 3. 顶栏统一（含 Python 顶栏重构）

### 3.1 你要的形态

```
┌──────────────────────────────────────────────────────────────────────┐
│ [← 大厅]   🐼 萌码 Python · 学习中心        [🟢 就绪] [☁️ 已同步] [⚙️] │
└──────────────────────────────────────────────────────────────────────┘
   左边：返回 + 学科 + **当前子页**        右边：状态 + 同步 + 设置
```

关键改进是**左边多一段「当前子页」**。现在四个页面的标题都是写死的学科名，
孩子进了「学习中心」或「复习」之后，顶栏完全看不出自己在哪。

```js
  actions: [ … ],            // 学科自己的主操作，**最多 2 个**
  status:  [ … ],            // 状态胶囊（引擎就绪 / 同步中 / 离线）
  settings: [ … ]            // ⚙️ 菜单项

Topbar.setSection("复习");    // 子页切换时调用，不用重挂
```

## 4. 统一账号与云同步（待审计补完细节）

### 4.1 目标（用户可见的部分）

**一个 8 位同步码，四个学科通用。** 孩子在平板上输入一次，
Python 的作品、英语的单词进度、打字的关卡、以后数学和汉字的记录，全部同步。

1. 先只读备份（导出 JSON）
2. 迁移是「复制」不是「移动」
3. 迁移后跑一次双向校验（旧键和新键的条数、等级、XP 对得上）

## 6. 英语内容修复方案

### 6.1 不只是改错，而是**把校验从「结构」升级到「语义」**

现在 `check_content.py` 全绿但内容有错。所以修复分两步：

**第一步：修掉已发现的错**（清单见审计结论）

**第二步：加一层语义校验，让同类错误以后不可能再出现**

| 校验项 | 做法 | 可行性 |
|---|---|---|
| 音标 | 引入一份权威发音数据（如 CMUdict 或 `eng-to-ipa`）自动比对 | 高 |
| 例句是否含该词 | 字符串匹配（含变形处理） | 高，纯自动 |
| 中文释义非空 / 非英文 / 无重复 | 规则 + 去重 | 高，纯自动 |
| 拼读分组与拼写是否自洽 | `phonics` 字段里的字母组合必须真的出现在 `word` 里 | 高，纯自动 |
| 释义与词是否对得上 | 需要人/模型抽检 | 中，抽检 |
| 关卡配置里引用的 id 是否都存在 | 已有 | ✅ 已覆盖 |

**判据**：修完之后，`check_content.py` 要能**报出语义问题**，
而不只是「结构没问题」。

### 6.2 修复纪律

- 每一处改动都要能追溯到「哪条数据、原来是什么、为什么错、改成什么」
- 改完跑一次全量回归（现有的 `e2e_smoke.mjs` 19 项 + 新的语义校验）
- **音频要重新生成**：释义改了可能不影响音频，但音标错了音频多半也错了

## 7. 数学岛（1–6 年级）

### 7.1 为什么数学是最划算的学科

**它不需要任何外部数据、没有授权风险，而且答案可以真算出来。**

仓库里已经有现成的模式可以照搬 —— Python 站的
`tools/py/exlib.py`：写「题目家族」时**真的把参考答案跑一遍，把真实输出
记作标准答案**。所以那 1318 道题的答案不会写错。数学完全一样：

```python
# 数学版 exlib：答案由 Python 算出来，不手写
def family_addition(a, b):
    return problem(expr=f"{a} + {b} = ?", answer=a + b)   # 真算
```

**这条决定了数学岛的内容成本远低于语文和英语** —— 题目可以是「生成」的，
而不是「写」的。

### 7.2 按能力维度组织（不照搬某套教材的目录，避免版权问题）

| 维度 | 1–2 年级 | 3–4 年级 | 5–6 年级 |
|---|---|---|---|
| **数感与运算** | 20/100 以内加减、表内乘除 | 多位数乘除、四则混合、运算定律 | 小数分数四则、因数倍数、百分数 |
| **量与计量** | 认识人民币、钟表 | 长度/质量/面积单位、年月日 | 体积容积、单位换算综合 |
| **图形与几何** | 认识图形、位置 | 周长、面积、角、对称平移旋转 | 多边形面积、圆、长方体正方体、圆柱圆锥 |
| **统计与概率** | 分类与整理 | 条形/复式统计表 | 折线/扇形统计图、平均数、可能性 |
| **代数初步** | 找规律 | 用字母表示数 | 简易方程、比和比例、正反比例 |
| **问题解决** | 图画应用题、和差 | 两步应用题、和差倍 | 行程/工程/植树/鸡兔同笼、分数百分数应用 |

### 7.3 内容怎么生产

| 题型 | 生产方式 | 单位成本 | 能出多少 |
|---|---|---|---|
| 口算 | **纯生成**（随机 + 约束） | 极低 | 无限（运行时按种子生成） |
| 竖式 | **纯生成**，答案真算 | 极低 | 无限 |
| 单位换算 | **纯生成** | 极低 | 数千 |
| 找规律 | **纯生成** | 低 | 数百 |
| 应用题 | **模板 + 参数生成**：人工写 60–100 个题型模板，每个生成 20 个数字变体 | 中 | 1200–2000 |
| 图形题 | **参数化 SVG**：写十几个图形生成函数 | 中 | 数百 |
| 统计图表题 | 生成数据 + SVG 画图 | 中 | 数百 |

**目标量（1–6 年级合计）**：口算/竖式等生成类 ~6000 题当量
（不占存储，运行时按种子出题）＋ 手写模板类 **1500–2000 道**。

### 7.4 交互

- **数字用大按钮键盘**（低年级不要求打字速度），支持物理键盘
- **竖式逐步揭示**：不直接给答案，孩子填每一步，错了立刻标出来
- **应用题**：选择题 + 关键步骤填空 + 线段图辅助
- **错题自动进记忆盒**（见第 9 节 F1）—— 这是平台化最直接的收益
- 限时挑战模式（口算）：给孩子"手感"，但**不排名、不比较**

## 8. 汉字岛（1–6 年级）

### 8.1 与数学相反：数据依赖重，授权要小心

| 能力 | 数据来源 | 授权 | 状态 |
|---|---|---|---|
| **笔顺动画** | `hanzi-writer`（37 KB）+ `hanzi-writer-data`（3500 字，**约 4 MB gzip**） | APL，**不传染**（有明确聚合条款） | ✅ 已核实 |
| **拼音** | `mozillazg/pinyin-data`（8105 字，62 KB gzip） | MIT | ✅ 已核实 |
| **古诗** | 唐诗宋词原文 | 公有领域 | ✅ |
| **组词** | 待定 | **待核实** | ⚠️ |
| **各年级生字表** | 待定 | **待核实** | ⚠️ D2 |
| **阅读理解** | 需全人工撰写 | — | 最贵 |

两个已知的坑（上一轮实测过，别再踩）：
1. `hanzi-writer` 内置的 `charDataLoader` **写死了 jsDelivr CDN**，必须覆盖成自己的路径
2. makemeahanzi 的 `svgs.tar.gz` **404**；`dictionary.txt` 是 **LGPL**，别用

### 8.2 分期（按「数据齐不齐」排，不按「好不好玩」排）

| 期 | 内容 | 依赖 | 成本 |
|---|---|---|---|
| **H1** | 认字 + 笔顺 + 描红 | 数据齐 ✅ | 中 |
| **H2** | 古诗（填空、连线、背诵） | 公有领域 ✅ | 中 |
| **H3** | 组词 / 成语 | **等授权** ⚠️ | 中 |
| **H4** | 阅读理解 | 全人工 | 高（最后做） |

**先做 H1**：它数据最全、交互最强（笔顺动画 + 描红是汉字独有的体验）、
而且**按需加载**——练到的字才下载，一个字约 1 KB gzip，不必一次推 4 MB。

### 8.3 交互

- **笔顺动画 + 描红**：`hanzi-writer` 自带 `quiz` 模式可以判定笔顺对错（接入时验证）
- **看拼音选字**（不做手写识别 —— 那需要额外的识别模型，成本不划算）
- **组词连线**
- **古诗填空**
- 渲染坐标要按 `viewBox="0 0 1024 1024"` + `scale(1,-1) translate(0,-900)`

### 8.4 需要你点头的两件事

1. **字表按什么分年级**（D2）
2. **组词数据用哪个** —— 我倾向先跳过 H3，等找到授权干净的词表再做，
   不要为了赶进度用来源不明的数据

## 10. 顺序与里程碑

### 方案 B：先看到新学科

## 三份审计的结论（已完成，全部有实测证据）

### 账号与同步：**账号早就统一了，不统一的是同步层**

这条路查清了，而且推翻了一个假设：

- Python / 英语 / 打字三个入口用的是**同一个 D1、同一张 `accounts` 表、
  同一个 `POST /api/account`**。所以「统一登录」在客户端只是一件事：
  **一次登录，把同步码写进三个地方**。
- 不统一的是同步层：三套客户端实现、三套端点、三张不同形状的表
  （Python 6 张专用表 / 英语 4 张 `en_*` 表 / 平台 1 张通用 `sub_rows`）。
- **新库 `mian-platform-db` 是空的**（所有表 0 行），所以**不需要迁移**。
- 老站 `mian-db` 里有 18 个孩子的 133 个作品 + 12 份进度，但那是**另一个
  origin、另一个库**，localStorage 天然不互通，同步码在库里只有哈希、
  不可逆 —— 想拿回来只能靠家长自己抄码。本次决定不迁移。

### 审计发现 6 个 bug，其中一个是**会真丢数据**的

| # | 问题 | 状态 |
|---|---|---|
| §6.1 | 平台内核 `save()` 无条件推进 `updated` → **跨设备恢复永远失效，且随后一次推送会把云端进度覆盖成 0** | ✅ 已修 + 14 项回归测试 |
| §6.2 | `sub_rows` 主键不含 `profile_id`，打字 `row_id` 又写死 → 多档案互相覆盖 | ✅ 已修 |
| §6.3 | 英语站设了 PIN 的账号拉不动数据；`setPin()` 字段名写错会**取消** PIN | ⬜ 待修 |
| §6.4 | 英语客户端从不发墓碑、`apply` 也不看 `deleted` → 删掉的档案会复活 | ⬜ 待修 |
| §6.5 | `/api/v1/sync` 超限**静默丢弃**，不回报（Python 端点有 `dropped` 记账） | ⬜ 待修 |
| §6.6 | 平台档案改名会被别的设备覆盖（`updated_at` 恒为 `Date.now()`） | ⬜ 待修 |

§6.1 的修法值得记下来，因为它是**教训**：

> `save()` 只在内容签名真的变化时才推进 `updated`；新增 `keepUpdated` 选项，
> 给「导入远端数据」和「`init()` 里的每日重置」用。
> 每日重置是按本地日期算出来的**派生状态**，每台设备都会自己算，
> 一旦让它推进 `updated`，「打开一次页面」就会让本地看起来比云端新，
> 于是云端进度全被拒绝、接着被空进度覆盖。
>
> 另外 `exportRow()` 不能在 `updated=0` 时回退成 `now()` ——
> 否则新设备一登录（`sync()` 是先推后拉）就把云端清零。

**这条链路的原有测试只断言 `typeof Sync === "object"`，完全覆盖不到，
所以是全绿但会丢数据。** 新增的 `tools/platform/e2e_sync_merge.mjs` 专门钉它，
修复前红 8 条。

### 手机兼容：17 条真问题（4 条严重）

| 严重问题 | 状态 |
|---|---|
| **键盘岛在手机上 0% 可用**：打字区是 div、屏幕键盘是 48 个 `aria-hidden` 的 span 没有 click，点它什么都不会发生，也没有任何提示 | ✅ 已修（触摸设备显示「需要实体键盘」，收到物理按键自动收起） |

**方法学教训（值得记住）**：`window.innerWidth` 不能当参照宽度。

必须用 `documentElement.clientWidth`。
